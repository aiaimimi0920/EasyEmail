# 自定义文件夹（W3）

本切片迁移平台内的邮件位置与层级管理，不创建 IMAP 或供应商远端文件夹。
网页和开放 API 共用数据归属、版本比较、层级约束和 W2 的原子整理回执。

## 位置与层级

- 每用户最多 100 个活跃文件夹，可建立多层父子结构；名称在用户范围内唯一，不按父级分别重复。
- 名称采用与标签相同的 NFC、trim、简单 Unicode lowercase 名称键、安全色和 40 码点限制。
- 同一邮件最多有一个自定义位置；标签仍是独立的多对多属性。
- 默认收件箱排除已移入自定义文件夹的邮件；“全部邮件”仍可读取所有未入回收站的位置。
- 自定义文件夹筛选只读取该文件夹直属邮件，不递归包含子文件夹中的邮件。
- 移动位置会取消归档，不自动从平台回收站恢复邮件；恢复仍需显式 `trashed:false` 与删除权限。
- 既有单封 PATCH 和批量 `archived` 显式赋值会在同一事务清除自定义位置，避免“移回收件箱”仍留在自定义位置。
- 删除文件夹将其直属邮件移回默认收件箱，保留正文、附件、标签和其他 flags；回收站状态不变。
- 删除父文件夹只将直属子文件夹移到根目录，不删除子文件夹或移动子文件夹中的邮件。
- 子文件夹被自动移到根目录时版本递增，旧编辑不能将它重新挂回已删除父级。

这些语义沿用旧桌面的“删除父级后子级移根目录、其中邮件回 Inbox”，但不直接复用 Tauri 或本地数据库 I/O。
单邮箱缓存列表仍保持既有读取范围，位置筛选在聚合工作台提供，不向旧 message summary/detail 自动追加私有文件夹信息。

## 接口与权限

| 接口 | 合同 |
| --- | --- |
| `GET /api/v1/folders?limit=100&cursor=UUID` | 活跃文件夹按 ID 分页，默认 25，最大 100，返回 parentId |
| `PUT /api/v1/folders/:uuid` | `{name,color,parentId,expectedRevision}`；创建版本 0，编辑比较当前版本 |
| `DELETE /api/v1/folders/:uuid` | `{expectedRevision}`；版本保护、清关联、重置子级和删除墓碑同事务完成 |
| `GET /api/v1/mailboxes/:box/messages/:message/folder` | 返回私有自定义位置或 null；不代表归档、回收站等 flags |
| `GET /api/v1/messages?folderId=:uuid` | 归属与活跃性校验；可与标签、系统 folder 和其他条件相交 |
| `POST /api/v1/messages/organize` | W2 命令增加可选 `folderId`，UUID 为移入，null 为默认收件箱 |

`folders:read` 允许读取定义与位置、按文件夹查询；`folders:write` 允许管理文件夹定义。
读取单封位置还需 `messages:read`，移动邮件还需 `messages:write`。
管理文件夹不等于允许删除邮件；回收站的写入仍单独要求 `messages:delete`。
原有 `messages:write` 的归档动作仍可改变系统位置，但不会返回文件夹元数据或获得定义管理权限。
网页登录写入校验 Origin；程序 Key 不自动获得新 scopes。

`folderId` 不可与同一批命令的 `archived` 同时出现，避免相互冲突的位置指令。
省略 `folderId` 与显式 null 不同：省略不改变自定义位置；null 明确移动到默认收件箱。
命令仍为 1–50 个唯一邮件 ID、8 KiB 请求上限，必须使用 UUID `Idempotency-Key`。

## 并发与失败

父级必须属于同一用户且未删除；自身和后代不可作为父级。
递归祖先条件在实际 INSERT/UPDATE 中重新判定，而不是只依赖请求早期的 SELECT。
两个同时通过预检的相互移动请求只能有一个成功，不能形成环。

移动文件夹复用 W2 的 operation ID fence 和 D1 batch：目标文件夹在预约写入时必须仍活跃。
目标删除、邮件 purged 或归属无效时整批失败，其他 flags/标签不会部分成功。
同 Key 重试只回放原回执，不重新移动，所以旧响应丢失后核对不会覆盖另一设备的新位置。
文件夹保存、删除与网页重试同样保留原 UUID、版本和内容，墓碑禁止旧 ID 复活。
旧命令未携带 `folderId` 时，其规范化对象和 hash 保持原样，W2 回执仍可原 Key 核对。
不携带新筛选字段的旧游标指纹保持原样；携带 folderId 的游标绑定用户和该筛选。

## 网页

聚合页提供层级管理、父级选择、完整路径选项、文件夹筛选和批量移动；详情提供单封移动。
父级选择不展示自身或后代，后端仍独立防环。
删除操作明确确认；取消不写入。删除当前筛选的文件夹后解除该筛选，返回默认位置查询。
管理标签和文件夹复用同一个 CAS 写入生命周期 hook，不复制两套丢响应重试逻辑。

未决网页操作仍是浏览器内存状态，不承诺刷新、关闭页面后自动恢复。
整理回执在 D1 持久保留，可用原 Key 查询；不将这一边界泛化到外部邮件投递。

## 升级与回退

新增 `0016_folders.sql`，只建立私有文件夹、位置表和索引；不改写旧数据或 Key。
**须先应用全部迁移，再启用新运行时**；新默认收件箱查询需要位置表，不能先切换代码再补表。
启用文件夹写入前应排空旧的整理写入实例，不承诺旧版运行时参与新位置规则。
回退必须保留新表、墓碑与 W2 幂等回执；旧版没有自定义文件夹页面，可能按旧规则将这些邮件显示在收件箱。
回退窗口应暂停整理写入或保持只读，不允许旧归档写入方继续并行修改新位置；恢复新运行时后再启用写入。
不执行 DROP、逆向清空位置、删除源项目或生产数据搬迁。

当前正式结果以 `folders-final/verification.json`、`folders-platform/verification.json`、
`folders-final/closeout.json` 的实际 status 为准，不沿用 W2 对新源码的验收状态。
验证涵盖并发防环、父级删除竞态、配额、归属、原子故障回滚、旧 hash/游标与 Chrome 丢响应、层级、移动、删除。
没有生产部署、真实远端文件夹操作或公网邮件投递验收。
会话、联系人、订阅、普通邮箱、Agent 以及 CC/BCC、附件发送与可靠投递队列仍需独立迁移。
