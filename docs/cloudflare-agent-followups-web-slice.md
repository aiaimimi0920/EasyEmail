# Agent 同线程跟进网页（W11h3b）

本阶段将 W11h3a 的 follow-up API 接入 `Agent 线程` 工作台：任务根和真实入站根均可显式回复，查看多封跟进记录、分页及单封详情，并在派发前取消指定跟进。
本阶段不增加 schema，不修改后端发送/收件规则，不包含后台自动收件、Agent OAuth、真实公网投递或生产发布。整体迁移仍未完成。

## 网页入口与安全边界

- 发件账号和实际收件地址来自服务器线程来源 context，不提供默认账号替换或任意收件地址输入。
- 原任务已跨提交边界时可选为回复对象；已提交的历史跟进也可显式选用；入站线程从现有安全邮件详情显式选择来信。
- 网页不拼接 RFC headers，提交的只有服务器消息 ID 和类型。服务器仍核对所有权、当前归属、版本与实际路由。
- 确认框显示实际 from/to；受限服务、前序发送不确定及来信发件身份未验证的风险仅在对应动作确认时提示。
- 只有 open/needs_attention 可以新建。人工归档/完成、派发状态、独立取消互不混用；SMTP accepted 显示为送达未确认。
- 保留 `SafeMailBody`、现有 R2/附件读取及服务器 MIME 构造，不执行邮件中的指令、HTML 脚本或远程资源。
- 新增 `agent-followups` Key 预设仅含 `agent-tasks:read`、`agent-threads:send`、`agent-inbox:read`，不扩张任何旧预设，也不授权配置、收件同步、原任务发送或人工状态修改。

## 未知结果与组件生命周期

`useAgentFollowups` 由 `AgentThreads` 父级拥有，不归可切换的详情表单所有。提交前复制完整 body，固定线程 kind/ID、实际地址及 UUID key。

1. 网络失败、5xx、429 或不匹配的成功 DTO 均保留未知操作；普通工作台导航不卸载该父级。
2. 核对发送先 GET 原 key。只有明确 404 才重发完全相同的 key/body，不能以新 key、修改确认位或另建任务代替核对。
3. 回执必须匹配原 key、root kind/ID、来源版本、回复对象、确认位和未清理内容；错误回执不能释放未知锁。
4. 原写入已确认后，后续来源/列表刷新失败只记读取错误，不重新变成未知写入。
5. 未知期间锁住本线程工作台的切换、筛选、人工状态、其他跟进及取消。线程写入与 follow-up 用同步 ref 互锁，不只依赖按钮下一次重绘。
6. 取消未知按原跟进 ID 只读核对，不自动重复 POST，不承诺跨 pending 后仍可取消。
7. 放弃本页核对需要风险确认，不撤销或重发服务器意图；清除当前来源，必须显式刷新后才能另起发送。
8. 不向 localStorage/sessionStorage 写凭据或正文；整页刷新或退出不保留未决表单，也不自动重放。服务器的持久意图、原键和发送记录不受此影响。

## 验证和回退

新增 DTO 测试覆盖原意图每个身份字段、清理后回执、来源 context 和同根分页。新增 Chrome 测试覆盖两类根、多封跟进与 MIME 父链、显式确认、取消、未知原键核对、导航/刷新/退出、受限和前序 unknown、最小 Key、分页、路由变化及 390px 布局。
测试使用隔离的本地 workerd/D1/R2 与合成 SMTP/IMAP，不等于真实服务商或 Cloudflare 云端验收。初始红测保留在 `agent-followups-web-red`；最终状态以 `agent-followups-web-final/verification.json` 为准。

本阶段修改仅限 Web、对应测试夹具、测试登记及文档，回退可恢复此前 Web bundle；0048 后端表和持久发送意图保持不动，不能用前端回退撤销已排队邮件。
