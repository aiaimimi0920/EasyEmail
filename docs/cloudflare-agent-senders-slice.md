# Agent 服务默认邮箱（W11f）

在独立 Agent 服务目录中保存、查询、修改和清除默认发件账号；任务网页支持显式选用该账号。
这是默认配置到任务创建的 Web/API 链路，不是后台自动发送、自动收件、未匹配来信建线程或完整 Agent 模块完成。

## 复用与权限

- 沿用 `POST/PATCH/GET /api/v1/agent-services` 及既有服务操作回执，没有第二套配置 API。
- 可写字段新增 `defaultSenderAccountId`：UUID 或 `null`。POST 省略表示未配置，PATCH 省略保持不变，显式 `null` 清除。
- 服务列表和详情返回 `defaultSenderAccountId: UUID | null`，不返回该账号凭据、SMTP 配置或额外邮箱详情。
- 只能引用同用户、尚未移除的 Agent 账号；普通账号、其他用户账号、未知或已移除账号均返回 `agent_service_sender_unavailable`。
- 默认值是目录元数据，可在 SMTP 配置前保存，也可保留已停用账号的引用；保存本身不连接 IMAP/SMTP，不构成发送授权。
- 沿用独立的 `agent-services:read/write`、同源 Session 写入和 Bearer scope 规则。服务目录 Key 不因此获得账号凭据或任务发送能力。

## 状态、事务与来源

默认值变更沿用服务 `expectedVersion`，更新服务版本、默认映射和完成操作回执处于同一个 D1 batch。
预约时同时核对最新服务版本、当前凭证/用户有效性及新默认账号尚未删除，不能用入口处的旧快照绕过。
同键重放只返回原回执，不恢复已清除的默认值；同键不同默认值冲突。事务中映射写入异常不会留下新服务版本或半完成回执。

账号后来停用、清凭据或移除时，配置不静默选用其他账号。移除后的引用仍可显式清除；账号墓碑保留 FK 身份，不因默认值而重新启用账号。
移除服务由 schema-owned trigger 清除其默认映射，包含旧 runtime 发起的服务墓碑；不会因此删除邮箱账号或服务器邮件。

## 显式任务与网页

服务编辑器可以按需读取本用户 Agent 邮箱选项、分页、设置及清除默认值；尚未加载的原默认 ID 保持不变，不被首项或空值替换。
任务页选择服务后提供“使用服务默认邮箱”，按确切 ID 读取账号，默认账号不在首 100 项时也不退回其他账号。
该读取先清空原选择和 SMTP；缺失或畸形响应不回退到原账号，停用或无有效配置时不能提交任务。
随后仍可以手动选择其他 Agent 账号作为本次显式覆盖，最终提交前展示实际发件地址并要求用户确认。

任务 API 保持 W11d 合同：必须明确提供账号 ID、账号 revision、SMTP revision 及 service version。
网页取默认值后同样提交这些明确版本，而不是把默认指针留给后台延迟解析；原 body/key 在结果未知时不改变。
未提供发送来源不会因为存在默认值就创建或发送任务。没有新增默认发送快捷 API，也不把默认配置当作已测试可投递账号。

与既有服务配置变更一致，改变默认值会增加服务版本，因此旧版本 queued 任务在派发预约时失败，不重定向到新默认账号。
编辑器对此提供即时确认。已经跨 guard 的任务仍保持原有不可重发语义；默认值不改写历史任务的账号、正文或投递结果。

另修复任务网页的确定状态缺陷：取得有效创建回执后，列表 GET 的 HTTP/响应校验失败仅报告列表刷新错误，不重建已经清除的未决操作，避免出现无法核对的假锁定。

## 扩展迁移与回退

`0044_agent_service_senders.sql` 只新增私有映射表、索引和服务墓碑 trigger。
两个同用户复合 FK 分别绑定实际服务和 Agent 账号；不改旧表定义、行、历史操作摘要、任务或凭据权限。
未携带新字段的旧 POST/PATCH 命令形状及 hash 保持不变；不导入缺少云端 owner 的桌面默认账号。

将来发布先应用扩展迁移再更新 runtime/Web；回退 W11e runtime 时保留新表和配置，不 DROP/清空。
旧 runtime 普通服务更新保留默认映射，服务墓碑触发清除；旧 API 不会接受默认配置字段，也不自动使用其发信。
