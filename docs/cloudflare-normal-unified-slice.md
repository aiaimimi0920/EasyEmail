# W10e：普通来源聚合、正文搜索与缓存提取

本切片把W10d普通收件接入同一个聚合收件箱，不借用临时邮箱身份，不新增桌面或NAS依赖。
整体迁移继续进行；本地实现与夹具验收不代表真实Cloudflare、真实邮箱或生产容量验收。
本文记录W10e历史边界；W10f已扩展普通平台状态和共同筛选，当前合同见[普通邮件整理](cloudflare-normal-organization-slice.md)。

## 统一查询与兼容

`GET /api/v1/messages?sources=all|temporary|normal` 提供显式来源选择，仍需 `messages:read`。
包含普通来源的 `all` / `normal` 另外要求 `mail-accounts:read`；旧Key不会自动扩权。
未提供 `sources` 的旧 `/messages` 合同保持临时邮箱范围、旧游标和权限，不隐式扩大数据可见范围。
网页增加独立的聚合只读、聚合下载及普通同步/阅读Key预设；原有预设的权限集合不变，新预设也不包含配置写入或发信权限。

- 临时结果带 `sourceKind=temporary` 和原 `mailboxId`，原有状态不变。
- 普通结果带 `sourceKind=normal`、`accountId`、`epochId`、UID与远端flags快照；不伪造平台已读/星标/归档状态。
- 普通详情、原文与附件继续通过受W10d保护的 `/normal-accounts/{id}/messages/...` 读取。
- `accountId`仅用于普通来源；未知或他人的账号404，非法格式400。不能同时传供应商或临时邮箱过滤器。
- 全部来源支持主题、发件人、收件人、正文/HTML的字面量搜索与收件时间范围。`%`与`_`不是通配符。
- `providerId` / `mailboxId`显式选择临时来源，不触发无关普通索引修复。
- 普通来源暂无平台整理状态，因此含普通来源时，已读、星标、标签、自定义文件夹、归档/回收站筛选明确拒绝，返回 `normal_filter_unavailable`；不会悄悄漏掉普通邮件后声称完整结果。

按收件时间倒序，空时间的旧临时记录仍以observedAt排序；同时间按来源与消息ID稳定排序。
游标绑定用户、来源、所有筛选与普通账号revision/epoch快照；两个来源即使消息ID相同，也不会去重或错开详情入口。
来源更换、移除、用户停用或epoch变化后，迟到结果不返回旧内容，旧分页不能跨来源继续。

## 搜索投影、旧数据与边界

新增0026的 `normal_inbox_search` 是已规范化内容的派生D1投影，不替代消息身份、R2原文或W10c游标。
新同步沿用同一个D1提交事务，把消息、投影、回执与检查点一起提交；不把正文放进批次manifest。
索引通过消息FK和content SHA关联；所有查询再结合owner、active用户、当前来源哈希、epoch和已提交batch。
未提交batch与失败R2写入不能形成可见投影。

0024/0025旧行允许暂时没有投影。查询每次最多从5个经大小/摘要核验的R2内容对象补建，最多读取10MiB对象字节。
补建写入包含账号revision、来源epoch和用户状态fence；重启和重复请求可继续，不改旧消息ID、flags、manifest或检查点。
仍有待补记录时返回409 `normal_index_pending`，网页供用户刷新继续；不把不完整索引当成空结果。
损坏或缺失内容对象拒绝补建，不返回部分成功页面。

当前每账号1000封累计预约、128MiB原文/内容预约的上限不变；D1投影增加了有界但真实的额外存储与写入成本。
普通账号最多20个，查询按当前用户来源范围执行；列表不把正文装入返回结果或前端。
当前搜索使用D1字面量条件，不是已完成生产压测的全文检索系统。大规模扫描、CPU、数据库读写量与成本必须另做真实平台测试。
自动旧epoch、staged对象、请求及投影清理尚未完成，不以硬限额代替长期维护。

## 缓存提码与认证链接

新增 `GET /api/v1/normal-accounts/{id}/extractions`，需 `messages:read` + `mail-accounts:read`。
复用现有提取条件与同一OTP/认证链接算法：必须指定since、精确当前收件地址、可选sender/subject/kind，排除未来异常时间和凭据URL。
普通提取每次检查最近10封符合时间范围的缓存，最多返回10项；`searched`、`searchLimit=10`、`searchLimited`明确表达搜索预算。
与旧临时来源的100封预算分别报告；不能把窗口内未匹配解释成整个邮箱无结果。
此GET只读缓存与必要派生投影，不连接IMAP、不标远端Seen、不访问认证链接、不创建发送任务。
响应 `sync.cachedOnly=true`，不声称刚完成同步或已检查整个远端INBOX。

网页普通账号页面复用提取表单和结果展示，仅启用缓存提取；不放置尚无安全同步合同的普通邮箱自动等待按钮。
后续仍要接通原键同步式等待、普通会话/订阅和整理/发送来源dispatch，不能据此取消这些目标。

## 网页与升级回退

聚合收件箱默认全部来源，提供来源选择、共同搜索和正确详情分派；普通邮件没有临时批量选择框或回复/整理假按钮。
需要临时邮箱特有筛选与会话视图时明确切到临时来源；旧整理、标签、文件夹、回收站、远端删除和发送不借用普通ID。
普通账号页与聚合详情共享同一个安全正文、附件与原文组件。浏览、搜索、提取和下载不自动重连。

升级先应用0026，再启用新查询/写入代码。旧writer产生的无投影记录可有界补齐；保留所有原表、对象和身份。
回退到W10d时保留新投影表，恢复旧网页与查询即可；不执行删表、删数据或源格式contract。
合并、部署、真实凭据导入、数据迁移及切流仍分别等待批准。
