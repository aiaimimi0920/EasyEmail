# W10g：普通邮件标签与自定义文件夹

本切片继续迁移普通邮箱工作台。它复用用户已有的私有标签和文件夹及其管理界面，
不建立第二份分类目录，不借用临时邮件的消息身份，不修改远端 IMAP 文件夹或标记。
本地实现不代表真实 Cloudflare、真实邮箱或整体迁移已经验收。

## 数据、位置与所有权

- 0028 仅新增 `normal_message_labels`、`normal_message_folders` 及筛选索引。旧普通消息、状态、回执、搜索投影及临时表定义不改变。
- 标签关联是多对多；文件夹关联是每用户、每普通消息唯一位置。关联只由当前普通账号 owner 的受控事务写入。
- 普通消息有独立的关联表，即使与临时邮件 UUID 相同，也不会互相修改。
- 自定义文件夹移动会清除平台归档；显式归档或移回收件箱会清除自定义位置。
- 默认收件箱排除自定义位置、归档及回收站。`all` 包含自定义位置但不含回收站。
- 自定义文件夹筛选与系统位置筛选相交；回收站邮件仍保留原位置及标签，恢复后回到原位置。
- 删除标签在同一事务内清除两种来源的关联；删除文件夹同时将两种来源的直接成员移回默认位置，保留回收站、正文、附件和子文件夹的原有安全规则。
- 标签或文件夹删除不要求普通来源的读取权限，也不返回普通消息、账号或成员计数；这沿用分类资源管理本身的权限，不授予邮件读取能力。

## 写入、查询与权限

原普通整理入口继续使用：

```text
POST /api/v1/normal-accounts/{accountId}/messages/organize
GET  /api/v1/normal-accounts/{accountId}/organization-operations/{key}
```

整理现在支持 `addLabelIds`、`removeLabelIds`、`folderId`，复用原输入规范化、1–50封上限及原键回执。
添加或移除标签需额外 `labels:read`；任何显式位置移动（包括 `folderId:null`）需 `folders:read`。
原有来源/消息读写权限及回收站删除权限保持不变，未修改旧 API Key 的 scopes。
账号 revision、来源 hash、epoch、用户 active、全部消息和分类资源归属均在同一写事务内检查。
任一目标失效，状态、分类关联和回执均不部分提交。

旧 W10f 的规范化请求 hash 不变。重试只返回原回执，不重放关联，且仍需原操作权限；
即使标签或文件夹后来被删除，已完成的原键仍可核对，新键不能使用已删除的分类资源。
原每账号10000条整理回执上限不变，自动保留维护仍待完成。

新增只读关联入口：

```text
GET /api/v1/normal-accounts/{accountId}/messages/{id}/labels
GET /api/v1/normal-accounts/{accountId}/messages/{id}/folder
```

它们校验当前来源、账号 owner、消息 committed 状态和独立分类读取权限，并在读取后核对来源未变化。
统一聚合支持全部来源的 `labelId` / `folderId`；普通账号列表增加 `folderId`，游标绑定系统位置和该自定义位置。
即使当前没有可用普通消息，也不跳过分类资源权限或归属检查。

## 网页

普通详情复用既有标签及文件夹组件，使用普通账号整理控制器，不调用临时邮件整理接口。
未确认操作仍在会话内存保留原键、消息与分类目标；跨页面保留，不自动重放，不写浏览器持久存储。
普通邮箱页支持自定义文件夹导航，聚合页开放共同标签和文件夹筛选。
新 `normal-taxonomy` Key 预设只允许普通缓存整理及分类读取，不包含分类管理、账号配置、同步、发信或删除。

## 升级、回退与后续

先应用0028，再启用新 reader/writer。切换前须排空旧普通整理及分类删除写入方，不允许新旧位置 writer 混跑。
旧 W10f writer 不认识普通自定义位置，不能依赖滚动混跑保持位置互斥；本切片不自动执行任何部署。
回退保留新表和数据、不执行 contract；旧代码会忽略普通分类并可能将自定义位置邮件重新显示在默认收件箱。
重新启用新版本前须核对回退期间的普通状态编辑；分类和回收站都不是访问控制或永久擦除边界。

混合来源批量网页、普通会话/订阅、草稿/发送、永久清除与安全保留维护继续迁移。
多文件夹 IMAP、远端状态、SMTP/OAuth2、Agent、更多供应商、旧数据迁移和真实平台容量/成本及收发验收仍在整体范围中。
