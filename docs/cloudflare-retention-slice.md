# M3f 平台自动到期与数据保留

## 范围与默认值

此切片仅在独立迁移工作区实现 Cloudflare EasyEmail 的平台访问期限和数据保留。
默认策略关闭，各项天数为 0；不会因为升级而给旧邮箱添加期限或自动清除旧内容。
它不是上游邮箱删除、远端凭据撤销、完整隐私擦除或生产迁移许可。

| 字段 | 范围与作用 |
| --- | --- |
| `enabled` | 启用后续分配期限及按天数自动清理 |
| `mailboxDays` | 新分配邮箱的平台访问期限；0 不设期限，不追溯旧邮箱 |
| `cacheDays` | 按平台首次 `observed_at` 清除邮件缓存正文、头部及附件 metadata |
| `trashDays` | 按 `trashed_at` 清除仍在回收站的缓存；恢复后不再按此项命中 |
| `outgoingDays` | 按 `updated_at` 清除非 pending 发送记录的地址、主题及正文 |
| `auditDays` | 按 `created_at` 清理供应商管理审计 `admin_audit` |

天数必须为 0–3650 的整数，0 表示不按该项清理。两个缓存条件按 OR 生效；
恢复回收站、收藏或星标不能豁免已满足的 `cacheDays`。
清理不可恢复；备份、上游和用户已下载的数据不受平台策略控制。

## 到期规则

新分配 guard 与最终邮箱存储相同 `expires_at`，同时记录策略版本。
地址分配只在供应商和保留策略的版本仍匹配时取得原子 guard。
取得 guard 后即按该版本执行；随后关闭或修改策略不延长已分配的期限。
原创建幂等键的结果核对优先，不会因配置停用或到期而重新创建地址。

到期在请求检查和 SQL 写入围栏立即生效，不等待 cron。
到期邮箱不能开启新的同步、发送或附件下载，也不能通过启用/停用复活。
缓存仍可读取、检索、提码和整理，并可显式释放平台访问。
返回的回复和附件下载能力随平台期限失效，不以缓存的 UI 状态代替后端权限。

维护将到期邮箱标为 `expired_at`，清除平台保存的邮箱凭据和同步 lease，
递增同步版本，阻止进行中的同步落库；不删除上游邮箱、不声称远端 JWT 已撤销。
已经取得发送 reservation 的外部请求可能完成，记录实际已知结果；原键仍可核对，不能自动重发。
即使随后关闭策略，已承诺的到期仍执行，其凭据回收不受 `enabled` 反向延长。

## 管理 API

全部入口仅允许有效的管理员网页登录会话；API Key 没有管理员权限。
写入和预览请求均校验精确 Origin，并使用独立应用限流。

```text
GET  /api/v1/admin/retention
PUT  /api/v1/admin/retention
POST /api/v1/admin/retention/preview
POST /api/v1/admin/retention/run
```

GET 返回 `policy`、`revision`、更新时间及最近完成批次。
PUT 请求为 `{expectedRevision, policy, confirm:"APPLY RETENTION"}`，
完整验证字段，通过 CAS 更新并在同一 D1 batch 写入最小策略变更记录。
冲突返回 `409 retention_policy_changed`，不能以旧页面覆盖新策略。
策略记录缺失或无效时返回 503，不静默回退为关闭策略后继续分配。

preview 请求为 `{expectedRevision, policy}`，可预览尚未保存的候选策略，
不修改邮箱、邮件或运行记录；安全限流计数仍会更新。
每类最多读取 101 个候选，返回最多 100 的下一批计数、`more` 和检查时间。
这是非锁定快照，期间新增数据和时间推移可能改变执行时计数。
不满足当前版本时必须刷新、重新预览。

run 请求为 `{expectedRevision, confirm:"RUN RETENTION"}`，还需 16–128 位
字母数字/下划线/横线的 `idempotency-key`。服务端按操作者哈希键并核验版本。
同键返回原批次结果，不因新积压而执行另一批；同键换版本返回冲突。
若响应丢失，应保留原键和原版本核对，不创建新键盲目执行。

## 原子批次与调度

每类每次至多 100 行：到期邮箱、邮件缓存、发送内容、供应商审计，合计至多 400 行。
默认 cron 每 15 分钟调用一次；以事件所属 15 分钟窗口和策略版本形成确定性 guard。
同一窗口/版本不会重复执行，后续窗口或新的显式手动批次继续处理积压。
各表清理和运行计数在一个 D1 batch 内完成：

1. 按策略版本与管理员身份围栏插入唯一运行 guard。
2. 选择并清理各类有限候选，记录实际影响行数。
3. 标记完成。任一语句失败则整批回滚，不留下部分清理或成功 guard。

未启用的内容清理目标使用 `WHERE 0`，不会为了默认关闭策略遍历正文大表。
到期查询使用期限索引；此处“有限候选”不等于已验收真实 D1 计费或大规模扫描成本。
最近批次按数据库插入顺序选取，不依赖秒级时间与随机 UUID 的排序。

邮件只清内容并保留 tombstone、指纹、组织状态和引用，防止同步复活旧版本。
发送保留请求键、请求哈希、配额计数、状态和时间；pending 不直接清内容。
原有定时维护可先把过时 pending 标为 unknown，再按保留期限处理。
维护 guard、用户身份、供应商凭据、最小策略变更记录不在此自动清理范围内。
这些最小记录会持续增长，后续需单独设计可证明不破坏去重/配额/防重放的压缩策略。

## Web

平台管理增加保留策略编辑、影响预览、确认保存与确认执行一批。
编辑后旧预览失效；保存后须按当前策略重新预览，不会顺带执行维护。
普通页面切换保持未决维护的原键；未知结果期间锁定策略编辑与新批次，提供“检查维护结果”。
刷新浏览器或退出登录会丢失页面内的未决操作上下文，应先保存并核对显示的键，不能以刷新当作取消。
维护记录在 D1 持久化，页面不把 key 或策略写入 localStorage/sessionStorage。

邮箱展示平台期限及到期状态，禁止新的同步、启用和写信；历史缓存阅读保持可用。
发送历史在内容已清除后仍有明确入口与状态，不出现空标题或伪装投递成功。

## 升级、验证与回退

新增 `0008_retention.sql`，仅扩展列、索引和独立策略/运行表；0001–0007 不改写。
0006/0007 升级测试逐列验证原值、密文、状态、指纹、发送 guard 和审计，
单独验证新增列默认为 NULL、策略关闭；重复迁移和重启不丢数据。
旧版本回退可忽略新增列，但旧代码不执行新的到期围栏，因此不能在启用新期限后宣称
任意回滚到旧二进制仍保持同样的到期保证；应回退至带围栏的版本或先停止写入。

本地回归覆盖默认关闭、字段验证、权限/Origin、CAS、晚段失败整批回滚、
幂等并发、有限批次及积压推进、同窗口调度、tombstone、发送 guard 保留，
以及进行中分配/同步/附件/发送的期限与版本竞态。
独立 Chrome 覆盖预览、取消、确认、未知响应后跨页面核对、到期缓存阅读、
已清发送内容、重启持久化、普通用户隔离及移动端布局。

完整验证结果以本轮 `m3f-final/verification.json` 与 `closeout.json` 为准，
历史 M3e 收据不覆盖本轮源码。未验收生产 D1 成本、真实供应商、远端资源回收和生产策略运维。
开发不读取生产邮件/凭据、不自动部署、不合并分支；原目录及 NAS 继续保留。
