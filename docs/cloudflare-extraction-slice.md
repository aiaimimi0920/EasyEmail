# Cloudflare 有界验证码与认证链接等待（M3i）

本切片补齐“按条件等待新结果”的本地 Web/API 链路，复用既有供应商同步、
租约、限流、消息缓存及 `service/base` 的提取算法。不是生产验收、后台收信任务
或验证码消费协议；不创建新邮箱、不发送邮件、不访问提取出的认证链接。

## 1. 单次检查接口

`POST /api/v1/mailboxes/:id/extractions/check` 同时要求 `messages:read`
和 `mailboxes:write`，会话请求还要求精确 Origin。两项 scope 均不隐含另一项，
管理员不能绕过资源归属；API Key 可在没有浏览器 Origin 时按相同规则调用。

```json
{
  "since": 1793149200,
  "recipient": "ee_example@cf.example.test",
  "sender": "noreply",
  "subject": "verify",
  "kind": "otp",
  "page": 1
}
```

- `since` 必填，为 UTC Unix 秒，规则与既有提取接口一致：大于零，不超过当前时间 60 秒。
- `recipient` 默认当前邮箱地址，提供时必须大小写规范化后精确相同。
- `sender/subject` 是大小写不敏感的包含过滤，不是发件人身份认证。
- `kind` 为 `any`（默认）、`otp` 或 `link`；只含链接的邮件不会结束 `otp` 等待。
- `page` 默认 1，后续仅接受当前邮箱已记录的下一页；未知字段、错误类型及非法过滤先拒绝，
  不因无效筛选先访问供应商。页码仍以同步时的 revision/lease 原子检查为准。

一次 HTTP 请求只同步一页，再查询平台缓存；没有 Worker 内轮询或长连接。
Cloudflare 每页最多 10 封；Temporam 仍受既有列表及逐邮件详情的单页请求预算约束。
与手动同步共用每用户每分钟 20 次额度及同一邮箱租约，不另开绕过通道。
暂停、停用、释放、平台到期、供应商停用、凭据不可用及同步冲突继续失败关闭。

成功响应包括 `items/searched/searchLimited/sync`，另有：

| 字段 | 含义 |
| --- | --- |
| `state=matched` | 本次缓存查询找到满足时间、地址、过滤及目标类型的提取结果 |
| `state=waiting` | 本次有限窗口没有匹配；不是完整远端邮箱无信的证明 |
| `retryAfterSeconds=5` | waiting 时建议的下一次检查间隔；matched 时为 null |
| `sync.nextPage` | 下一次允许检查的页；为 null 时下一轮从第 1 页开始 |
| `sync.complete/missing` | 仍保留既有同步完整性语义，不冒充一致性快照 |

最多扫描最近 100 封符合时间窗的缓存邮件，最多返回 10 项。
`searchLimited=true` 或 `sync.complete=false` 时必须向使用者保留截断/缺失信息。
没有已知上游收件时间、早于 since、超过允许时钟偏差、已回收/清除及地址不符的邮件不匹配。
查询再次绑定用户和邮箱 ID；不存在跨用户缓存回退。

上游认证、限流、超时、存储及租约错误仍返回原有脱敏错误，不把旧缓存结果包装成同步成功。
`GET /mailboxes/:id/extractions` 继续只读缓存、不请求上游，新增可选的相同 `kind` 过滤。

## 2. 网页与独立程序等待

网页“提取缓存邮件”继续使用表单中的缓存时间起点。
“等待新结果（60 秒）”则固定点击时的 UTC 秒作为 since，固定当前邮箱地址、
发件人、主题和目标类型；整个等待期间不会滚动 since 或放宽过滤以凑出结果。
新结果按上游收件时间判断，不以平台观察时间冒充新信。
同一秒内更早收到的邮件仍可能位于这个秒级边界，这是时间精度限制，不承诺一次性消费。

等待串行发起单次检查，检查间隔至少 5 秒，最多 12 次且总时限最多 60 秒，
两项上限先到即停；每次按返回的下一页继续，遍历结束再回到第 1 页。
找到结果、请求失败、到期、暂停、停用、释放、切换工作台、切换邮箱、退出或刷新页面后，
不会继续启动后续检查；超时会中止浏览器正在等待的 HTTP 响应。
结果显示收件时间；只展示链接文字，不创建自动导航或后台访问。

“停止等待”只停止这个页面流程，不是上游请求撤销协议。
停止前已经进入服务端的单次读取仍可能在 15 秒上游期限内完成并写入自己的缓存；
旧响应不会重新填入已停止或另一个用户/邮箱的页面。没有跨刷新自动续跑或浏览器持久存储。
后台标签页可能被浏览器节流，不保证精确每 5 秒执行；恢复后仍检查已过时限，不补发错过的轮次。

独立程序可以调用相同接口，保存固定的 since/recipient/filters，串行按
`sync.nextPage ?? 1` 轮询，并自行施加总时限、次数上限及至少 5 秒间隔。
遇到 401/403、生命周期、供应商或同步错误时应停止并处理原因，不能静默换邮箱。
API 是单次检查合同，不会替调用方创建持久化等待任务或代其无限重试。

## 3. 数据、兼容与回退

不增加数据库表/列，不修改 0001–0010 的历史迁移，不复制提取算法。
`extraction-query.ts` 拥有过滤与缓存提取，`extraction-check.ts` 负责授权和单页编排，
`syncMailboxPage` 继续拥有全部限流、凭据、租约及原子缓存规则。
`ExtractionPanel.tsx` 拥有网页请求生命周期，`extraction-poll.ts` 拥有有界轮询状态。

现有 GET 与 POST sync 合同保留；回退到 M3h 不需要删除数据，需使用匹配的旧 Web。
开发回退仍可继续使用未改动的原目录与原部署；不导入生产数据、不自动发布或切流。

## 4. 证据和未验边界

`extraction-check.test.mjs` 覆盖 workerd/D1 中的条件、新鲜度、目标类型、分页、
跨用户、scope、Origin、限流/租约、生命周期及无错误缓存回退。
`extraction-poll.test.mjs` 验证串行顺序、12 次/60 秒预算、生产 deadline 分支的中止（单测快进计时器）、
取消/失败停止以及迟到成功拒绝；Chrome 测试验证真实页面收取新 OTP/链接、固定条件、
停止/导航/暂停/退出、移动端、无浏览器持久存储及没有访问邮件外链。
这些测试接入 `npm test` / `npm run test:web`。

本轮独立完整收据使用
`linshi/easyemail-cloudflare-migration-20261028/m3i-final/verification.json` 和 `closeout.json`。
历史收据不覆盖本轮源码；真实供应商投递、生产 Worker CPU/D1 成本、远端未知资源恢复、
更多供应商、完整后台和后续邮件工作台仍须独立实现及验收。
