# DuckMail 临时账户接入（W12c）

把旧 SDK 的 DuckMail 临时邮箱收件链迁到 Cloudflare 聚合 Web/API，不要求桌面、Userscript 或 NAS。
本地最终结果以 `duckmail-final/verification.json` 的实际 `status` 为准；合成验收不等于真实凭据、邮件投递、云端发布或整体迁移完成。

## 官方合同与范围

2026-10-31 联网核对官方 `https://www.duckmail.sbs/en/api-docs` 与 `/llm-api-docs.txt`，Base URL 为 `https://api.duckmail.sbs`。
原始响应与响应头保存在 `linshi/easyemail-cloudflare-migration-20261028/remaining-provider-contracts/`。
只读抓取公开文档，没有读取真实凭据、创建真实账户或查询用户邮件。
文档提供集成接口不等于取得任意公共聚合商业授权；部署者仍须核实实例权限、域名、配额与服务条款。
本切片仅处理 SMTP 临时账户，不处理 Microsoft 托管/导入，不提供 DuckMail 发信。

## 显式区分两种上游访问

- 默认或 `authentication: "api-key"`：平台 API Key 访问域名与创建接口，缺 Key 阻断，不自动降级匿名。
- 仅 DuckMail 可配置 `authentication: "anonymous"`：按官方合同使用公共域名及公共临时账户创建，不读取或回退平台 Key。
- 平台登录、用户归属、API Key 权限、Origin、配额不变；上游匿名不表示平台向匿名访客开放邮箱。
- 管理员可在网页选择访问方式，真实 `secret.configured` 仍表示是否配置了凭据，不为匿名模式伪造“已配置 Key”。
- 显式匿名模式探测只读取完整公共域名列表并检查白名单，是接口连通/合同探测，不是凭据认证。
- API Key 模式探测返回 `409 provider_probe_unavailable`：域名接口允许无凭据，不能用其成功证明 Key 有效，不为此创建账户。
- 模式变化进入配置 revision/hash；旧匿名探测成功不会成为 Key 模式的成功健康结果。缺 Key 时新分配不可用。
- 清 Key 不回退环境凭据；显式匿名模式的匿名访问仍保留，网页风险确认准确说明该边界。

## 创建、身份与重试

使用平台强随机前缀、全局地址预约、用户归属与原键回执，显式调用一次 `POST /accounts`，要求 HTTP 201。
创建密码采用强随机值，只在该次调用链内存在，不落 D1，也不发回浏览器。
随后不带平台 Key 调用密码登录 `POST /token`，核对账户 ID，再用邮箱 Token 请求 `GET /me` 核对 ID/精确地址。
只把邮箱 Token 与账户 ID 加密存储；同步仍先核对 `/me`，不把平台 Key 当作邮箱 Token。
复制到另一邮箱的密文因用户/邮箱上下文不匹配而失败，且不会触发供应商请求。

创建明确传入 `expiresIn: 86400`，不用永久账户的 0/-1；本地采用 24 小时与平台更短策略的较早期限。
创建、登录 ACK 丢失、身份不一致或本地落库失败保留 `unknown`，`retrySafe: false`。
同一个幂等键只核对原结果，不再创建；不执行补偿删除，不靠换键或轮换凭据掩盖未知结果。
密码不保存意味着此类未知账户无法自动重新登录；保留未知回执，不能宣称已恢复或已删除上游账户。

## 有界 Hydra 分页与缓存

域名和邮件按官方每页 30 项读取，验证 `hydra:member`、`hydra:totalItems`、页数、数量及唯一 ID。
页指针只核对同源、固定路径和唯一 `page` 参数，不跟随响应提供的任意 URL；请求路径由本地构造。
域名完整读取，最多 1,000 项；跨页数量改变或重复域名失败，不截断后假装完整。
邮件每页最多 30 次详情，加 `/me` 和列表最多 32 次 HTTP 读取；邮件上限 30,000，沿用平台 1,000 页边界。
每个响应最多 2 MiB，单次操作整体 15 秒 deadline，无自动重试；429 不立即重试，交给既有平台冷却和显式重试边界。

邮件列表和详情均验证账户 ID/收件地址，详情还验证精确消息 ID。
详情 404 计入 `missing` 且不宣告完整；其他 HTTP/JSON/身份/超限错误不覆盖已确认缓存。
邮件和状态沿用同一 D1 batch、lease、revision、用户及到期 fence，失败事务和过期持有者不能写入缓存。
只用数字页码，不虚构上游 cursor，不增加 schema；重启后可以请求后续页。
上游分页不是事务快照，页间来信或删除可能改变顺序并造成重复/遗漏；本地按 ID 去重，用户可从第一页刷新，不保证持续流入中的精确快照。
`complete` 只描述当次列表已到最后一页且没有缺失详情，不证明上游没有延迟到达、未公开截断或并发变化。

## 阅读能力与非目标

支持手动/自动分配、域名白名单、管理员配置、加密凭据、显式同步、聚合、纯文本/安全 HTML、缓存提码与 Web/API。
附件仅保存文件名、类型和大小等元数据，不保存、暴露或跟随 `downloadUrl`，不宣称附件下载可用。
不宣称支持自选前缀、地址恢复、条件远端删除、源邮件下载、DuckMail 发信、Microsoft 托管或真实 API Key 预检查。
平台本地已读/星标/归档/删除不冒充上游对应操作。

## 兼容、回退与验收

旧供应商没有新字段时配置序列化/hash 不变，原有数字页码、持久 cursor、密文、邮件与回执保留。
回退前先停止新配置写入和 DuckMail 操作，停用/移除新类型配置并保留备份；旧运行时不认识 DuckMail，不能无条件混读。
无需删除表、清理未知回执或执行 NAS 双写；没有自动提交、推送、合并或部署。

本地覆盖独立 HTTP 合同夹具、Worker/D1、匿名与 Key 模式、失败事务、跨用户、原键未知、重启、过期 lease 与独立 Chrome。
冻结候选重新运行受影响的四个旧供应商、配置、权限、分配、创建、缓存、附件和发信拒绝回归，另做 checker、类型/构建、52 个本地迁移、重复 apply、FK 与 Wrangler dry-run。
不以此前 GPTMail 收据替代本轮验收；不是全仓/全部 Agent OAuth 重跑。
真实授权、真实邮件、Cloudflare 网络与成本、数据迁移和切流仍未验收，整体迁移继续保留未完成状态。
