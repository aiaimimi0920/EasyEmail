# W10h：混合来源批量网页

本切片接通聚合收件箱的普通邮件选择，以及普通多账号与临时邮件的共同批量整理。
它复用原有整理 API，不新增跨来源事务，不修改远端 IMAP，也不代表真实 Cloudflare 或邮箱收发已验收。

## 选择与提交

- 网页整体最多选择50封。身份包含来源、普通账号和消息ID；普通与临时消息UUID相同也不会串选。
- “选择当前页邮件”替换为最近加载的一页，加载更多后不把此前全部页暗中加入；改变查询或刷新结果清空选择。
- 仅临时消息仍走既有临时批量控制器，保留原按钮、原键和重试合同。
- 包含普通消息时，先把临时消息合为一组，再按普通账号分组、稳定顺序串行提交。
- 每组冻结独立请求键、账号、消息ID和操作字段；后续选择、导航或数组修改不能改变已保留的请求。
- 支持已读、星标、归档、移回收件箱、回收站/恢复、标签和自定义文件夹。移到回收站在发请求前即时确认。
- 每个子请求保留原后端权限和原子性；临时来源与不同普通账号之间没有全局事务或补偿回滚。

## 部分结果与恢复

每组分别显示未执行、处理中、已完成、被拒绝、结果未确认或已取消。
成功数量只计算已确认成功组，不将已完成组说成回滚或重新发送。

遇到首个拒绝或未确认结果即停止；后续组仍是未执行，只有用户显式继续才会提交。
未确认组未解决前不能继续其他组，也不能把它取消成“未执行”。
“取消未执行组”只取消尚未发送的组，保留已完成、被拒绝和未确认组。

未确认组提供两个不同操作：

- 只读核对：临时组读取 `/organization/{key}`，普通组读取账号限定的原回执；不发送 POST。
- 原键重试：仅重试该组已冻结的正文和键，不重新发送成功组，不更换新键。

GET 404、权限收回、网络错误或原键重试被拒绝，都不能证明此前未知请求没有提交，仍保留未确认状态。
核对成功不会自动启动下一账号。回执键或消息数量不匹配也不当作成功。

## 网页会话与边界

批量计划由当前登录用户的会话级内存控制器持有，跨工作台导航保留。
共享网页整理门闩在请求开始前同步占用；混合批量、普通单封和临时原键整理控制器不会在同一页面会话中互相穿插启动。
它不是服务端锁，不阻止其他设备、独立 API 调用方或管理员操作；后端围栏与幂等回执仍是权威。
普通/临时旧控制器也保留“曾未确认”分类，原键重试后来收到4xx时不丢弃原键。
门闩不代替所有网页操作的全局锁；例如先启动的同步和独立临时PATCH仍由后端状态规则处理。

注销会卸载控制器，迟到回包不会启动后续组或更新另一个用户的界面。
不使用 localStorage/sessionStorage，不建立自动后台重试或跨完整刷新恢复；完整刷新和注销会丢失内存计划。
普通账号配置仍通过既有普通控制器锁定，未确认结果在导航后继续可见。

## 升级与回退

本切片只改变 Web 和测试/文档，后端 API、数据库及权限范围不变；无需新迁移。
部署仍须满足 W10g 的0028与写入方切换要求。本切片不自动执行部署、导入、切流或合并。
回退静态资源不删除数据或回执，但会丢失网页内存计划；切换前应核对未确认组并排空浏览器写入。

普通独立账号页的批量列表、会话/订阅、草稿/授权发送、永久清除和安全保留维护继续迁移。
多文件夹远端同步、SMTP/OAuth2、Agent、更多供应商、旧数据迁移及真实平台容量/成本和收发验收仍在整体范围中。
