# W10i：普通邮箱独立页批量整理

本切片补齐“普通邮箱”独立账号页面的多选与批量整理，不要求先进入聚合收件箱。
复用现有普通整理 API、会话级原键控制器和共享批量组件；不新增后端接口、权限范围、数据库迁移或依赖。

## 选择与动作

- 每个列表属于当前普通账号，最多选择50封；切换账号不会把旧账号的选择带到新账号。
- “选择当前页邮件”替换为最近成功加载的一页，不把所有已加载页暗中全选。
- 可在不同已加载页手动累积选择，到达50封后只允许取消已有选择。
- 刷新缓存、改变平台文件夹、成功整理后重新读取及导航后重新读取均清空选择；没有浏览器持久化选择。
- 支持批量已读/未读、加星/取消星标、归档/移回收件箱、回收站/恢复、标签添加/移除、自定义位置移动。
- 批量移入回收站必须即时确认。取消确认不发请求，不删除远端邮件。
- 提交前复核目标仍属于当前账号和已加载列表；权限与整批原子性仍由后端判定。

## 原键与互斥

每次提交冻结当前账号、消息ID、操作字段和原键，使用现有普通整理控制器。
未知结果继续锁定原操作，可“核对原普通整理”只读 GET，或“重试原普通整理”以相同正文和键 POST。
后续403、GET404或网络失败不会抹掉此前未知的提交；只读核对不重放写入，原键回放不覆盖后续独立编辑。

整理进行中或结果未知时，独立列表、普通账号修改和共享原键整理入口保持锁定。
这是当前网页会话的整理协调，不是服务端全局锁，也不能取消已经提交的请求。
跨工作台导航仍由同一普通整理控制器持有未确认请求；完整刷新和注销仍不承诺恢复内存上下文。

## 分页读取生命周期

刷新和加载更多共用可中止的列表读取所有权。
刷新或更换查询会中止旧请求，并用读取代次拒绝迟到页，避免旧分页覆盖新列表。
读取期间禁用邮件选择、批量整理和继续加载；缓存刷新仍可用来替换在途读取。
读取失败展示错误，不冒充同步或整理成功；同步已经明确失败时，随后的自动缓存刷新不会抹掉该失败提示。

所有动作只改变平台缓存状态；不自动登录、同步、发送，也不执行 IMAP STORE、COPY、MOVE 或 EXPUNGE。

## 验证与回退

新增 Chrome 场景覆盖真实本地 D1/R2/HTTP 整理、共享标签/位置、即时确认、未知提交原键恢复和导航互斥。
分页边界及迟到读取使用明确的合成列表响应，只验证网页状态机，不冒充真实51封邮件同步或公网投递验收。
正式收据使用 `normal-batch-final-r2/verification.json`，仅以实际状态为准，不沿用 W10h 收据覆盖新源码。
首轮冻结验证在源码审查复现同步失败提示被清除后主动中断，保留原现场，不把中断或此前专项绿灯冒充最终验收。
