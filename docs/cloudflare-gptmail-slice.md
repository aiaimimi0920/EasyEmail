# GPTMail 授权接入（W12b）

将旧 SDK 的 GPTMail 收件能力接入 Cloudflare 聚合 Web/API，不要求桌面、Userscript 或 NAS。
实际本地验收以 `gptmail-final/verification.json` 的 `status` 为准，不代表真实凭据、投递、云端发布或整体迁移完成。

## 官方合同与授权边界

2026-10-31 联网核对 `https://mail.chatgpt.org.uk/api/`、`/llms-full.txt` 与 `/terms/`（条款更新于 2026-10-16）。
原始响应、响应头和文本在 `linshi/easyemail-cloudflare-migration-20261028/gptmail-public-contract/`。
未抓取或内置每日共享测试 Key，未读取真实凭据、创建真实地址或读取任何用户邮件。
仅接入管理员有权使用的服务和 API Key；公开文档和未发现禁止代理条款不等于取得第三方公共聚合商业授权。
GPTMail 公共地址不是私密邮箱，知道地址的人可能读取邮件。平台隔离不代表上游排他所有权，不用于主恢复邮箱或敏感数据。

官方允许已知受支持域名时本地组成地址并直接查询。此切片采用这一路径，不请求 `/api/generate-email`：

- 管理员必须明确配置已授权域名，不抓取域名页面，不猜测未公布的域名接口。
- 分配随机强熵前缀，沿用 D1 全局地址预约、幂等回执和归属；不认领用户自选或已有地址。
- 分配只是平台随机地址，不是上游创建、永久保留或私密租约；能力目录为 `random-address`。
- 邮件最多保留 1–24 小时是上游邮件保留规则，不是邮箱地址生命周期。地址期限仅遵循平台策略，不伪造 24 小时地址到期。
- 相比旧 SDK 的远程生成路径，这是有意选择的已公布替代能力，避免生成写入限流与未知写入重试。

## 凭据探测不伪报成功

本轮无凭据只读请求已确认 `/api/stats` 返回 HTTP 200，且有公共缓存头，不能证明 API Key 被接受。
官方未公布能单独验证凭据、又不创建地址或读取邮箱的可靠接口。
因此管理员探测返回 `409 provider_probe_unavailable`，不请求上游、不写成功健康状态、不清除分配冷却。
网页显示即时必要错误；不增加解释型面板。配置 Key、分配成功均不等于凭据有效，首次显式收信才进行真实鉴权。
现有 Cloudflare、Temporam、MoEmail 的探测语义不变。

## 有界列表与本地分批

只使用官方固定路径 `GET /api/emails?email=...` 与 `GET /api/email/{id}?email=...`，每次都带精确邮箱，不按全局 ID 查询。
官方列表只有 `emails` 和 `count`，未公布可用分页协议；不自行添加 `page`、`limit` 或虚构上游 cursor。

- 单次列表最多 200 封、单响应最多 2 MiB；每批最多 10 次详情，连同列表最多 11 次 HTTP 读取，整体 15 秒 deadline。
- 列表数量必须与 `count` 一致；重复/非法 ID、收件地址错误、显式尚有更多或未知续页信号均整批失败。
- 超过限制明确失败，不截取后谎报完成。`complete` 仅表示已处理当次公开 API 返回的完整列表，不证明上游不存在未公开的截断规则。
- 将排序后的全量 ID 与邮箱地址计算 SHA-256；持久 cursor 为列表摘要和偏移。列表顺序变动不影响续页，增删 ID 则返回 `provider_snapshot_changed`。
- 变化后用户点击刷新，从第一页重建批次；已缓存邮件保留且去重，不自动循环或无限追赶流入中的列表。
- 续页复用 0052 的一邮箱一行存储，和邮件缓存、revision 同 D1 batch，复用用户/lease/状态/到期 fence；无新 schema。
- 详情必须匹配 ID 和收件人；详情 404 计入 `missing`，不会显示完整。HTTP 错误、HTML、重定向、无效 JSON、超限响应均不覆盖确认缓存。
- 不自动重试或轮换 Key，不将上游错误正文或 Key 写回浏览器。

## 支持与不支持

已接入管理员配置、端点允许名单、API Key 加密、手动/自动随机分配、显式收信、正文缓存、聚合、提码、Web/API 与重启续页。
不宣称支持 GPTMail 发信、自选前缀、地址恢复、远端删除、附件下载、私密/会员域名授权或真实 Key 预检查。
部署者必须先核实实例合同、域名权限和配额；不能用本地合成夹具结果替代第三方许可。

## 兼容与回退

不改变已有供应商、邮箱、消息、密文、创建回执或数据结构；旧数字分页不触及 cursor 表。
回退时先停止新配置写入和 GPTMail 操作，再停用/移除新类型配置并保留备份；旧运行时不认识 `gptmail`，不能无条件混读。
无需删除数据表或清空回执，也不执行 NAS/新旧双写。当前阶段未 commit、push、merge 或 deploy。

本地验证覆盖独立 HTTP 合同夹具、Worker/D1、双用户隔离、失败事务、过期 lease、列表变化、重启续页与独立 Chrome。
冻结候选重新运行受影响旧供应商回归、类型/构建、checker tests/ratchet/strict、52 个本地迁移、重复 apply 和 Wrangler dry-run。
不是全仓/全部 Agent OAuth 重跑；真实授权、真实邮件、生产成本与网络、旧数据迁移和切流仍未验收。
