# W10c：普通邮箱私有收件存储与原子检查点

本切片继续 W10b 的字节读取/MIME 基础，实现在 `service/cloudflare`。这是内部持久化收件原语，不是普通邮箱聚合 Web/API 已完成，也不是生产或真实账户收件验收。
后续W10d已在此基础上开放独立来源的同步/阅读/下载与网页，当前接口和升级边界见[普通邮箱同步阅读](cloudflare-normal-inbox-slice.md)；本文“尚无公开入口”描述W10c自身的历史切片，不覆盖W10d状态。

## 存储与身份所有权

- 新增 `0024_normal_inbox.sql`，只扩展独立 `normal_inbox_state`、`normal_inbox_batches`、`normal_inbox_messages`；不删除、重建或放宽旧表、旧地址唯一索引、旧 provider 合同。
- 普通账号不伪造临时邮箱地址、不借用临时邮箱 lease，不写入旧 `mailboxes`/`messages`。同一外部地址可由不同用户独立配置，来源身份与对象路径分别隔离。
- 当前仅 INBOX。来源哈希绑定服务器身份、用户名、账号收件地址和 INBOX；名称、密码轮换或重新启用本身不重置远端身份。更换远端账号/服务器或 UIDVALIDITY 切换生成新 epoch，旧 UID 不继承新正文、附件或本地状态。
- 消息身份由账号、INBOX epoch、UID 唯一确定。相同 Message-ID 或内容摘要不合并不同 UID；重新同步相同检查点不重复入库。旧 epoch 保留用于后续明确的可见性与保留策略，不混入当前来源。
- D1 保存身份、不可变对象引用、摘要、字节数、受控 FLAGS、时间、回执与游标。原始 MIME 和规范内容 JSON 放入可选私有 `INBOX` R2 binding，不复用发送附件的 `OUTBOX`，不把大正文塞入 D1。
- 默认部署配置没有 INBOX binding。缺失时在打开网络连接前明确拒绝，不创建真实 bucket 或导入真实邮件。未来 bucket 必须私有，不开启公开 URL，不把对象 key 当访问授权。

## 事务、重试与失败

1. 验证账号归属、版本、启用状态、服务器白名单哈希与凭据，校验独立 `mail-accounts:sync`；每用户每分钟10次、全平台60次内部同步限流。
2. D1 领取90秒 claim，固定 account revision 和 state version。只有配置版本变化或 lease 过期才可替换仍占用的 claim；旧执行者的释放操作只匹配自己的 token。
3. 执行 W10b 有界只读网络批次，全部 MIME 解析成功后才准备写入计划。网络或 MIME 失败不推进持久游标，不把部分成功冒充完整批次。
4. 在写 R2 前持久记录 staged intent，列明全部对象 key、摘要、字节数及显式 skipped。R2 put 使用 SHA-256 与不可覆盖条件；不重用其他批次的对象。
5. 最终提交前核对全部对象 head 的字节数和 SHA-256。一个 D1 batch 内重新检查 user active、账号 revision/启用/未移除、claim token/lease、state version，再发布回执、插入全部身份、推进游标并释放 claim。
6. 同一事务中任何插入失败都会回滚回执和游标。重复提交只核对原 intent，不再次入库；模糊数据库响应先查询原回执，不能仅因连接报错认定回滚或换 token 重放。

R2 与 D1 不存在跨服务事务。失败或进程中止可能留下部分对象，但写入前已有 staged manifest；失败分支不盲目删除可能已提交的对象。该 intent 及其容量持续计入限额，不能把对象遗留说成已清理。
清理 lease 失败时由90秒期限兜底，不覆盖已提交回执或原错误。尚无自动重试、自动清理或生产保留任务接线。

每封原文最多2 MiB，规范内容 JSON 最多2 MiB；沿用每批最多3封、100个 UID 数值窗口与网络总限额。每账号最多1000个批次回执、累计1000封预约邮件、128 MiB原文和规范内容预约容量，staged 与旧 epoch 都计入。
容量达到上限明确停止，不推进检查点，不淘汰身份或回执。上述是本地基础阶段的硬边界，不是已完成长期生产容量维护。后续须先实现可审核、按 epoch/租约保护的对象清理与数据保留，再开放持续同步。

skipped 仅允许 `message_missing` 与 `message_too_large`，与提交检查点在同一回执中持久保存。返回 complete 只表示到本次 UIDNEXT 快照，没有把空窗口、跳过或新到邮件说成已经全部入库。

## 可见性、兼容与回退

- 没有新增公开 `/normal-accounts/{id}/sync`、普通邮件阅读或附件下载路由；测试专用入口只在测试 Worker 构建内。旧 `messages:read` Key 不自动扩权，普通存储也不被旧缓存查询隐式读取。
- 后续公开接入必须统一处理列表、正文、聚合、会话、订阅、提码、下载、整理/删除、历史回执、草稿/发送和生命周期；不能只在列表补一个 scope。HTML 仍须走已有安全展示层。
- 远端 FLAGS 目前只是观测快照，不代表本地已读/星标或实时远端状态；不开放 STORE/MOVE/EXPUNGE/SMTP。
- 先应用0024，再运行了解新存储的内部读取方。旧运行时仍可读写旧表；回退暂停普通收件，保留新表、对象、身份与回执，不执行破坏性 contract。
- 后续共享 UI/查询可基于独立来源投影整合，不能把旧临时邮箱缓存写入方冒充普通 UID 权威方。当前没有生产双写、迁移真实旧数据或切换现网。

## 验证边界

专项测试使用真实本地 workerd、D1、R2 API 与合成 IMAP transport，验证重启持久化、二进制摘要、同内容不同 UID、来源/用户隔离、epoch 变化、稀疏窗口、显式跳过、对象写入失败、事务回滚和晚到结果 fence。
这不证明真实 TLS/密码可用、真实投递、边缘 CPU/并发/成本、长期容量维护、普通聚合界面或整个迁移完成。最终状态以证据目录独立 verification 收据为准，不沿用 W10b 绿灯覆盖新源码。
